Chapter 06 · Core skill

React components, JSX, props, and events

React helps divide a screen into reusable pieces. A component is a JavaScript function that returns JSX—markup-like syntax that describes what the UI should show.

Estimated time: 40–60 minRead, type, explain, practice

Purpose and objectives ¶

In the previous chapter, JavaScript learned to fetch and shape JSON. Now we need a reliable way to turn those values into a screen. React is a UI library: it lets you describe a screen as a tree of small functions, then updates the browser when the inputs to that tree change. This chapter is about the parts you can understand before state and backend wiring.

By the end, you should be able to:

  • explain a component as a function from inputs to rendered UI;
  • read and write basic JSX, including expressions, attributes, and fragments;
  • pass props, compose children, render a data-driven list, and use stable keys;
  • connect an event handler without doing work during render; and
  • choose a sensible boundary between a page, a reusable display component, and an event-owning parent.

Vocabulary and the component mental model ¶

A component is a capitalized JavaScript function that returns JSX. JSX looks like HTML, but it is JavaScript syntax that describes what React should render. A prop is an input supplied by a parent, much like an argument passed to a Python function. An event handler is a function React calls after an interaction such as a click.

Use this mental model: data flows down, events flow up. A parent owns the data it received or will later store in state. It passes a snapshot of that data to children as props. A child displays the snapshot and calls a callback prop when the user asks for something. The child does not secretly edit the parent’s data.

Component boundaries should follow a job, not an arbitrary number of lines. A TaskBoard can coordinate a screen, a TaskList can map records to rows, and a TaskRow can explain one record’s markup. Split when a piece is repeated, has a clear responsibility, or would be easier to test and explain on its own.

Render
React calls component functions and turns their returned description into browser elements.
Composition
Building a larger UI by nesting smaller components, often through a children prop.
Key
A stable identifier for an item in a rendered array; it is for React’s matching, not for display.

JSX: markup with JavaScript expressions ¶

JSX uses familiar tags but has a few rules. Close every tag, use one outer element (or a fragment), write className instead of HTML’s class, and put JavaScript expressions inside curly braces. Strings can use quotes; values such as numbers, objects, and expressions use braces.

JavaScript / JSXfunction TaskRow({ task }) {
  const label = task.done ? "Done" : "Open";

  return (
    <li className="task-row">
      <strong>{task.title}</strong>
      <span>{label}</span>
    </li>
  );
}

The parameter destructuring reads the task prop. The ternary chooses a label from the record. The curly braces insert the computed values into the output. The parentheses make the multi-line return unambiguous. React sees a list item containing a strong title and a status span; it does not send this function to SQLite or replace your backend.

Capitalization matters: <TaskRow /> means “call my component,” while <li> means “create a built-in browser element.” A component can contain HTML elements and other components, so a page becomes a readable tree.

Worked example: compose a task screen ¶

Start with the same kind of records introduced in the JavaScript chapters. These two records show only the fields the screen needs; a saved Task also carries created_at under the contract in Chapter 01. The parent has an array and a callback. The list knows how to iterate. The row knows how to display one task. The panel supplies a visual wrapper through children.

JavaScript / JSXconst tasks = [
  { id: 101, title: "Check stock levels", done: false },
  { id: 102, title: "Send supplier email", done: true }
];

function Panel({ heading, children }) {
  return (
    <section className="content-card">
      <h2>{heading}</h2>
      {children}
    </section>
  );
}

function TaskRow({ task, onSelect }) {
  return (
    <li>
      <button type="button" onClick={() => onSelect(task.id)}>
        <strong>{task.title}</strong>
        <span>{task.done ? "Done" : "Open"}</span>
      </button>
    </li>
  );
}

function TaskList({ tasks, onSelect }) {
  return (
    <ul>
      {tasks.map((task) => (
        <TaskRow key={task.id} task={task} onSelect={onSelect} />
      ))}
    </ul>
  );
}

function TaskBoard() {
  function handleSelect(taskId) {
    console.log("Selected task", taskId);
  }

  return (
    <Panel heading="Today’s tasks">
      <TaskList tasks={tasks} onSelect={handleSelect} />
    </Panel>
  );
}
  1. TaskBoard is the screen-level parent. It supplies the array and defines what selection means.
  2. Panel receives a title and nested JSX. Whatever appears between its opening and closing tags arrives as children.
  3. TaskList calls map. Each record becomes one TaskRow, and task.id is the stable key among siblings.
  4. TaskRow renders the record and passes the selected ID upward. It does not mutate task.
  5. The arrow function in onClick waits until the click. Then it calls onSelect with the current task’s ID.

Notice that the current callback only logs. Chapter 07 will replace that behavior with state so the selected task can appear on screen. Keeping this chapter’s components stateless makes the data flow visible first.

Events, rendering, and boundaries ¶

Rendering should be a predictable description: given props, return JSX. An event handler is the place for interaction work. Write onClick={handleSelect} when the handler needs no extra argument. Write onClick={() => onSelect(task.id)} when the click must carry a value. Do not write onClick={handleSelect()}; that calls the function while React is rendering, before anyone clicks.

Keep database and process details outside TaskRow. Its callback can later call the API client or Tauri command chosen in Chapter 01; the packaged trade-offs are revisited in Chapter 10.

Boundary test

If a component can be shown with sample props, it is probably a good display component. If it must know a URL, SQL statement, process lifetime, or secret, that concern belongs outside the display tree.

Common mistake → symptom → fix ¶

  • Calling a handler in JSX: the log appears during page load, or the screen loops. Fix: pass the function, or wrap arguments in an arrow function.
  • Using an array index as a key: after sorting or removing a row, the wrong row appears to keep focus or local state. Fix: use the record’s stable database ID.
  • Mutating props: code such as task.done = true does not create a reliable React update. Fix: call a parent callback; the parent will later update state and pass a new value.
  • Lowercase custom component: <taskrow /> is treated like an unknown HTML tag. Fix: capitalize component names.
  • Missing one JSX parent: the compiler reports adjacent elements. Fix: wrap them in one element or a fragment.

Beginner exercise

Create StatusBadge({ done }) that returns a <span> containing “Done” or “Open.” Then revise TaskRow so it renders StatusBadge instead of writing the ternary inline. Finally, explain why key={task.id} belongs on TaskRow in the parent’s map, not inside StatusBadge.

Show the worked answer and explanation
JavaScript / JSXfunction StatusBadge({ done }) {
  return <span>{done ? "Done" : "Open"}</span>;
}

function TaskList({ tasks, onSelect }) {
  return (
    <ul>
      {tasks.map((task) => (
        <TaskRow key={task.id} task={task} onSelect={onSelect} />
      ))}
    </ul>
  );
}

StatusBadge has one clear display job and receives only the value it needs. The list owns the array operation, so it is the nearest component that can give each sibling a unique key. The key helps React match rows when records are inserted, removed, or reordered; it is not a prop that TaskRow reads.

Recap and next-step bridge ¶

React components are capitalized functions that return JSX. JSX combines markup with expressions. Props carry read-only inputs down the component tree; composition and children let parents provide flexible structure. Lists use map and stable keys. Event handlers are passed, not called during render, and callback props let a child report an interaction without owning the application’s data.

Next, Chapter 07 adds state and forms. You will turn the selection callback into a real screen update, handle controlled input, and connect rendered data to asynchronous backend responses. Keep today’s boundary in mind: the React tree describes the interface, while FastAPI or Tauri/Rust remains a separate choice for privileged work and persistence.
