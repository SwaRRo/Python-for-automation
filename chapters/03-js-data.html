Chapter 03 · Foundations

JavaScript values and data structures

JavaScript is the language that gives the interface behavior. Start by learning how to name values and organize data into records and lists.

Estimated time: 35–50 minRead, type, explain, practice

Purpose and objectives ¶

JavaScript makes a screen respond to a person. Before a button can save a task or a list can show database rows, the program needs names for values and a predictable shape for each record. This chapter uses a small task feature as its running example.

By the end, you should be able to choose const or let, tell a primitive from an object or array, read and update a record, distinguish null from undefined, and design a JSON-safe shape that can cross an app boundary. You will also translate each idea into familiar Python terms.

Vocabulary and mental model ¶

Think of a variable as a labeled place in your program. The label is not the value itself; it gives you a way to refer to a value later. A primitive is one simple value: a string, number, boolean, null, undefined, bigint, or symbol. An object groups named properties, and an array is an ordered object-like collection whose positions start at zero.

A beginner distinction is “copied value” versus “shared reference.” A primitive assignment copies the value; an object or array assignment copies a reference to the same underlying record.

Binding versus contents

const prevents a variable binding from being pointed at a different value. It does not freeze an object’s contents. For React state, you will normally create a new object or array instead of mutating the old one, because a new reference makes a change easy for React to detect.

property
A named value inside an object, such as task.title.
index
A zero-based position in an array, such as tasks[0].
reference
A link from a variable to an object or array.
JSON-safe
Data made only from JSON values: objects, arrays, strings, finite numbers, booleans, and null.

const, let, and primitive values ¶

Prefer const when the variable will not be assigned a different value. Use let when the binding must be reassigned, such as a counter or a value that arrives later. Avoid the older var in new code; its function-scoping rules make beginner mistakes harder to see.

JavaScriptconst title = "Prepare report"; // string: text
const priority = 2;              // number: numeric data
const isDone = false;            // boolean: true or false
const dueDate = null;            // deliberately no date
let serverResult;                // declared, but currently undefined
serverResult = "saved";          // let permits reassignment

Line by line: the first four bindings use const; the last starts as undefined and is later assigned. A const declaration must have an initializer, so const serverResult; is a syntax error.

JavaScript is dynamically typed, so inspect values at a UI boundary instead of guessing. typeof helps, but typeof null historically returns "object"; use value === null for an explicit null check.

Objects and arrays model app data ¶

An object literal uses braces and stores key–value pairs. It is close to a Python dictionary, but JavaScript usually reads a known key with dot notation. Bracket notation is useful when the key is stored in another variable.

JavaScriptconst task = {
  id: 7,
  title: "Prepare report",
  done: false,
  created_at: "2026-10-06T08:30:00Z",
};

console.log(task.title);       // "Prepare report"
const field = "title";
console.log(task[field]);      // "Prepare report"

task.done = true;              // changes this object’s property

The braces create one record. task.title reads a known key; task[field] reads a key chosen at runtime. The final line mutates this object. It is legal with a const reference, but a React state update will later use a copied object.

An array uses square brackets and preserves order. Its first item is index zero, and length counts items. The common app shape is an array of records:

JavaScriptconst tasks = [
  { id: 7, title: "Prepare report", done: false, created_at: "2026-10-06T08:30:00Z" },
  { id: 8, title: "Book a room", done: true, created_at: "2026-10-06T09:00:00Z" },
];

console.log(tasks.length);       // 2
console.log(tasks[0].title);     // "Prepare report"
console.log(tasks[1].done);      // true

Read left to right: choose the array, item 0, then its title. An index is not a database ID: index 1 currently holds the record with ID 8. The persisted Task also carries created_at; every stored record follows the contract in Chapter 01.

Worked example: prepare one task for the app ¶

Start with an in-memory list so its shape is visible. These are complete examples of the shared Task record; the API will later supply the same fields from FastAPI or a Tauri command.

JavaScriptconst tasks = [
  { id: 7, title: "Prepare report", done: false, created_at: "2026-10-06T08:30:00Z" },
  { id: 8, title: "Book a room", done: true, created_at: "2026-10-06T09:00:00Z" },
];

const firstTask = tasks[0];
const display = {
  id: firstTask.id,
  label: firstTask.title,
  status: firstTask.done ? "complete" : "open",
};

console.log(display);
// { id: 7, label: "Prepare report", status: "open" }

tasks is an array; firstTask refers to item zero; display is a view projection containing only the fields this row needs. The persisted record still has the shared created_at field. The conditional expression turns false into "open"; Chapter 04 explains decisions.

These records follow Chapter 01’s shared contract. React renders them from state; the full Rust-command versus FastAPI-sidecar choice is mapped in Chapter 01 and revisited in Chapter 10.

null, undefined, and JSON-safe shapes ¶

Use null for intentional absence; undefined usually means a value was not supplied or a property does not exist. They are different signals. The optional dueDate below is a hypothetical extension, not part of the course-wide Task contract. Adding it to a real app would require changing the API and database together.

JavaScriptconst optionalDueDate = null; // hypothetical extension field
const incompleteDraft = {};
console.log(optionalDueDate);       // null: deliberately no due date
console.log(incompleteDraft.owner); // undefined: no owner property

const jsonText = JSON.stringify({
  title: "Prepare report",
  dueDate: optionalDueDate,
});
const copy = JSON.parse(jsonText);
console.log(jsonText);
// {"title":"Prepare report","dueDate":null}

JSON.stringify makes request/response text; JSON.parse makes JavaScript data again. A JSON-safe shape uses objects, arrays, strings, numbers, booleans, and null. Functions, symbols, and undefined do not belong in it: an undefined property is omitted during stringification. Avoid non-finite numbers such as NaN in an API payload.

Shape first, transport second: decide what one task means, then let the UI and backend agree on that shape.

Python comparisons that prevent translation errors ¶

Your Python experience transfers well: an object resembles a dictionary, an array a list, and null resembles None. undefined has no exact everyday Python equivalent. Both languages use zero-based indexing and mutable dictionaries/lists.

Pythontask = {"id": 7, "title": "Prepare report", "done": False, "created_at": "2026-10-06T08:30:00Z"}
print(task["title"])
JavaScriptconst task = { id: 7, title: "Prepare report", done: false, created_at: "2026-10-06T08:30:00Z" };
console.log(task.title);

Python spells booleans True/False, uses None, and commonly uses brackets for dictionary lookup. JavaScript uses lowercase true/false/null; dot notation is common. Python raises KeyError for a missing key, while JavaScript returns undefined, so validate an API response before rendering.

Common mistake → symptom → fix

  • Mutating a shared reference → a second variable or a UI row changes unexpectedly → copy the outer object/array for a change; React will practice this pattern in Chapter 07.
  • Using an array index as an ID → editing the wrong task after sorting or deleting → use the record’s stable id for identity and the index only for position.
  • Confusing missing with deliberately empty → a request omits a field or a screen shows “undefined” → choose null for intentional emptiness and check optional properties before displaying them.
  • Mixing text and numbers → "2" + 1 produces "21" instead of 3 → inspect the value and convert validated input at the boundary.

Beginner exercise

Create a JSON-safe array named notes with two objects. Each object must have a numeric id, a string title, a boolean pinned, and a reviewedAt value. Make the first note not yet reviewed. Then print the second title and a JSON string of the whole array. Before opening the answer, explain which values are primitives and which value is the reference to the collection.

Show worked answer and explanation
JavaScriptconst notes = [
  { id: 1, title: "Idea", pinned: false, reviewedAt: null },
  { id: 2, title: "Meeting", pinned: true, reviewedAt: "2026-10-07" },
];

console.log(notes[1].title);       // "Meeting"
console.log(JSON.stringify(notes));

notes is a const binding to an array reference. Each id and reviewedAt value is a primitive; each brace-delimited note is an object, and the array contains both objects. The first reviewedAt is null because “not reviewed” is intentional. The second access uses index 1, which means the second item, and then reads its title. The final line creates transport text without functions or missing values, so it is safe as a basic JSON payload.

Recap and next-step bridge ¶

Use const by default and let only for reassignment. Primitives are simple values; objects describe one record; arrays order many values. Variables holding objects share a reference, so copying matters when a change should be isolated. Use null for intentional absence and recognize undefined as not supplied or not found. Keep API data JSON-safe and separate the React UI from SQLite through either a Tauri/Rust command or a deliberately managed FastAPI sidecar.

Next, Chapter 04 turns these values into behavior: if/else decisions, functions, and map/filter operations will derive the rows and capacity rules your task screen needs.
