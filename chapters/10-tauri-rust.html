Chapter 10 · Desktop integration

Tauri, Rust, and the desktop boundary

Tauri turns a web frontend into a desktop application. Learn the boundary between the webview and native host, plus enough Rust vocabulary to read a command.

Estimated time: 50–75 minRead, type, explain, practice

Purpose and objectives

Earlier chapters gave React state, FastAPI validation, and SQLite persistence. This chapter shows how that feature becomes a desktop application without pretending the layers disappear.

By the end, you should be able to:

  • Describe the Tauri v2 webview, Rust host, command, capability, and permission mental model.
  • Read a small Rust function, including types, borrowing, and Result.
  • Trace one task record from a React button to trusted code and back.
  • Choose between direct Rust/local SQLite access and a separately packaged FastAPI sidecar.
  • Explain what packaging and code signing do, and what they do not do.

1. The desktop boundary: one window, several processes ¶

Tauri is a desktop shell around a web frontend. React still renders JSX in a system webview and JavaScript manages loading, forms, and visible state; the difference is that a Rust host can perform selected desktop work.

Think of a guarded doorway rather than a magic connection:

  • React/webview: displays the task list, gathers a title, and asks for an operation.
  • Tauri command/Rust host: receives a deliberately named request, validates trusted-side rules, and performs native work.
  • SQLite: stores records. React does not open the SQLite file directly.
  • FastAPI sidecar, if chosen: is another Python process. Tauri does not start or secure it automatically.

Boundary rule

A frontend check such as “title is not blank” improves the experience, but it is not the security boundary. A command or API must check again because frontend code can be changed, interrupted, or compromised. Expose a narrow action such as validate_task_title, not “run arbitrary SQL.”

2. Vocabulary and the Tauri v2 mental model ¶

Command
A Rust function marked with #[tauri::command] and registered with the application so JavaScript can invoke it.
Invoke
The frontend call that sends a command name and a JSON-shaped argument object and receives a Promise.
Capability
A named policy connecting one or more windows/webviews to allowed permissions, often stored under src-tauri/capabilities.
Permission
A specific allow/deny rule, such as a plugin operation or permission to run one named sidecar.
Scope
A restriction inside a permission, for example which paths, windows, or command arguments are acceptable.
Sidecar
A bundled external executable, commonly a Python API or CLI, launched as a child process of the desktop app.

In Tauri v2, capabilities say which webviews may use privileged surfaces. They reduce accidental exposure but cannot repair unsafe Rust or a broad scope, so review both command code and capability configuration.

3. Worked example: invoke a safe task command ¶

This command is deliberately validation-only: it returns a TaskDraft containing a cleaned title and does not claim to save a Task or generate a database ID. A real command must call a storage repository, then return the complete shared Task record with an authoritative ID and timestamp. Rust’s Result makes failure part of the function’s type rather than hiding it.

Rust — src-tauri/src/lib.rsuse serde::Serialize;

#[derive(Serialize)]
struct TaskDraft {
    title: String,
}

#[tauri::command]
fn validate_task_title(title: String) -> Result<TaskDraft, String> {
    let clean_title = title.trim();
    if clean_title.is_empty() || clean_title.chars().count() > 120 {
        return Err("Title must contain 1–120 non-space characters".into());
    }
    Ok(TaskDraft {
        title: clean_title.to_string(),
    })
}

Read it line by line. struct TaskDraft groups the cleaned title in a known shape. String owns text. The derive line lets Serde send the draft as JSON to JavaScript; it has no database ID because this example has not saved anything.

The attribute marks validate_task_title as callable, while title: String declares the input type. The return type is Result<TaskDraft, String>: success is Ok(TaskDraft), failure is Err(message). trim gives a view of the text without outside spaces; to_string creates owned text for the returned draft.

Registration is the second half of the feature. A command that is written but not registered is not callable:

Rust — register the commandtauri::Builder::default()
    .invoke_handler(tauri::generate_handler![validate_task_title])
    .run(tauri::generate_context!())
    .expect("error while running Tauri application");

The builder collects configuration; generate_handler![validate_task_title] adds the command to the invoke table; run starts the desktop loop. expect reports a startup failure, not a user-facing validation error.

Now the React handler can send the same field name:

JavaScript — React event handlerimport { invoke } from "@tauri-apps/api/core";

async function saveTask(title) {
  try {
    const task = await invoke("validate_task_title", { title });
    console.log("Validated draft (not saved)", task);
  } catch (error) {
    console.error("Could not save task", error);
  }
}

invoke returns a Promise. The command name must match the registered Rust function, and the JavaScript object property title maps to Rust’s title argument. This example only previews a validated draft; do not add it to the saved-task list or show “Saved” until a repository has persisted it and the command returns the full Task.

4. Capabilities, permissions, and packaging ¶

Capabilities are configuration, usually JSON or TOML files in src-tauri/capabilities, that name windows and list permissions. For example, a main-window capability might allow a narrowly chosen core operation. Do not copy a broad permission list just because a generated example contains one; add the smallest permission required, then test the intended window.

Packaging turns the project into platform-specific bundles or installers by compiling the Rust host and frontend assets. It does not automatically create migrations, backups, a server, or authentication. Code signing identifies the publisher and helps detect tampering, but signed code can still contain a bug.

A sidecar must be bundled for each target architecture and explicitly permitted. Tauri’s shell plugin checks that rule before executing it. A Python API sidecar therefore needs a startup handshake, loopback-only binding, shutdown handling, crash reporting, and a rule that prevents arbitrary arguments. Never bind a local ERP sidecar to every network interface just to make the browser find it.

5. Choose direct Rust or a FastAPI sidecar ¶

Direct Tauri/Rust path: React invokes a Rust command; Rust validates and uses a SQLite library or Tauri database plugin. This is attractive for an offline, single-user task tracker because one desktop process can own local storage. It requires learning enough Rust to review queries, errors, migrations, and file locations.

FastAPI sidecar path: React talks to a Python API over loopback, or Tauri mediates that call. FastAPI keeps the Python validation and database code from Chapter 8, which is useful when the rules already exist or Python is the team’s strength. In exchange, the packaged app contains an additional executable/environment and must coordinate process lifecycle, port selection, health checks, logs, upgrades, and permissions.

For multiple computers, local SQLite does not create shared data: use an authenticated server and treat the desktop app as a client. Decide from offline needs, sharing, backups, and updates—not from assuming Tauri chooses for you.

Common mistake → symptom → fix

  • Wrong command name or field. Symptom: the Promise rejects with an unknown command or missing argument. Fix: compare the string passed to invoke, the registered function, and the JSON key character for character.
  • Forgot registration. Symptom: the Rust function compiles but the webview cannot invoke it. Fix: add it to generate_handler! and restart the dev process.
  • Trusting only React validation. Symptom: blank or malformed records appear when a caller bypasses the form. Fix: validate again in Rust or FastAPI before writing.
  • Confusing a sidecar with a library. Symptom: Python is missing, the port is occupied, or the child remains after exit. Fix: bundle the executable, grant only its shell permission, and design lifecycle behavior.
  • Granting broad capabilities. Symptom: a frontend compromise has unnecessary filesystem or shell reach. Fix: narrow permissions and scopes, then test each window.

Beginner exercise

Trace a user submitting Call supplier . Name (1) the React action, (2) boundary call, (3) trusted validation, (4) stored record, and (5) visible result. Then choose direct Rust or a FastAPI sidecar for an offline tracker and give one tradeoff.

Show a worked answer and explanation
  1. React’s submit handler reads the controlled input and may show a loading state.
  2. It calls invoke("validate_task_title", { title: " Call supplier " }), or calls the chosen FastAPI endpoint if the project keeps Python.
  3. The trusted layer trims the value, rejects an empty result, and applies the same rule even if the UI is bypassed.
  4. The saved record is { title: "Call supplier", done: false }, plus an ID and timestamp when persistence is implemented.
  5. React adds the returned record to state on success; on failure it stops loading and displays a retryable message.

Direct Rust with local SQLite is reasonable offline: fewer processes and no port lifecycle, but database code and errors move into Rust. A sidecar is valid when Python rules matter more; its executable, permissions, health check, and shutdown path become part of the feature.

Recap and next-step bridge ¶

Tauri v2 is a webview plus a native Rust host, connected through explicit commands and guarded by capabilities and permissions. Rust’s structs describe record shapes; types make inputs and outputs visible; Result makes success and failure part of the command contract. Packaging creates a distributable desktop bundle, while signing helps establish publisher identity. Direct Rust/SQLite and FastAPI sidecar architectures can both be correct, but their lifecycle, security, and update costs differ.

In the capstone, keep the same contract while building a complete task feature: list records, create one, mark it done, persist it, and test restart and failure behavior. Choose the integration path before wiring the button, then follow the record through UI state, validation, storage, response, and error display.
