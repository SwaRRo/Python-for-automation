React components, JSX, props, and events

React helps divide a screen into reusable pieces. A component is a JavaScript function that returns JSX—markup-like syntax that describes what the UI should show.

Estimated time: 40–60 minRead, type, explain, practice
Concise version. This preserves the earlier, shorter lesson. Open the expanded Chapter 06 lesson for the full walkthrough.

By the end, you can…

  • Define and compose React function components.
  • Pass values through props.
  • Handle a user event and render a list with stable keys.

Components are UI building blocks ¶

A React component is normally a capitalized JavaScript function. It returns JSX, which resembles HTML but lives inside JavaScript.

function TaskRow({ task }) {
  return (
    <li>
      <strong>{task.title}</strong>
      <span>{task.done ? "Done" : "Open"}</span>
    </li>
  );
}

The curly braces inside JSX insert JavaScript expressions. JSX must be returned inside one parent element (a fragment <>...</> is an invisible grouping element). JSX uses className rather than HTML’s class.

Props pass inputs downward ¶

Props are inputs supplied by a parent component. They make a child reusable. The child should treat its props as read-only and ask the parent to perform changes through a callback.

function TaskList({ tasks, onSelect }) {
  return (
    <ul>
      {tasks.map((task) => (
        <li key={task.id}>
          <button onClick={() => onSelect(task.id)}>
            {task.title}
          </button>
        </li>
      ))}
    </ul>
  );
}

The parent uses <TaskList tasks={tasks} onSelect={handleSelect} />. A callback prop lets the child report an event without owning the whole data model.

Events and rendered lists ¶

Pass an event handler function to props such as onClick or onSubmit. Usually pass the function itself, not call it during rendering: onClick={handleClick} is different from onClick={handleClick()}.

Use .map() to transform records into JSX elements. Every element in the list needs a stable key unique among its siblings. A database ID is usually a good key. React uses keys to understand additions, removals, and reordering; they are not merely a warning suppressor.

What React does not do: It does not define your backend, validate data securely, or make a database. It renders a UI from inputs and responds to changes.

Practice it

Create `TaskBadge({ done })` that displays “Done” or “Open,” and a `TaskList({ tasks })` that renders each task title using `.map()`. Use a stable `task.id` key.

Show answer guidance

A ternary is fine for the small label: return <span>{done ? "Done" : "Open"}</span>. In the parent, use tasks.map(task => <li key={task.id}>...</li>). If the conditional grows, compute a named value or use an if/else statement.
