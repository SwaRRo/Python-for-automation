Chapter 05 · Core skill

Async JavaScript, HTTP, and JSON

A desktop interface often waits for a backend or database. Learn how JavaScript waits for that result without freezing the whole window.

Estimated time: 45–60 minRead, type, explain, practice
Concise version. This preserves the earlier, shorter lesson. Open the expanded Chapter 05 lesson for the full walkthrough.

By the end, you can…

  • Explain a Promise as a future result.
  • Use async/await and handle network/HTTP errors.
  • Serialize request data and parse JSON responses.

The Promise mental model ¶

A network request takes an unpredictable amount of time. JavaScript starts the operation and keeps the event loop free to handle rendering and user input. A Promise is an object representing a value that may be available later—or a failure.

Mark the function async and use await to write the steps in a readable order:

async function loadTasks() {
  const response = await fetch("http://127.0.0.1:8000/tasks");
  const tasks = await response.json();
  return tasks;
}

await pauses this asynchronous function at that line. It does not stop the entire application from responding. Think “wait here for this function’s result, while the rest of the UI can continue.”

HTTP and JSON are a boundary ¶

HTTP sends a request to a URL with a method such as GET (read), POST (create), PUT/PATCH (change), or DELETE (remove). A request may include headers and a body. JSON is a common text format for request and response bodies.

const newTask = { title: "Prepare report", done: false };
const response = await fetch("http://127.0.0.1:8000/tasks", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(newTask),
});

JSON.stringify() converts a JavaScript value into JSON text. On the response side, await response.json() reads and parses JSON text into a JavaScript object/array.

Check failures explicitly ¶

fetch rejects for network errors, but an HTTP 404 or 500 still gives you a response object. Check response.ok before treating it as success. Use try/catch for failures and finally for cleanup.

async function createTask(task) {
  try {
    const response = await fetch("http://127.0.0.1:8000/tasks", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(task),
    });
    if (!response.ok) {
      throw new Error(`Save failed (${response.status})`);
    }
    return await response.json();
  } catch (error) {
    console.error("Could not save task", error);
    throw error;
  }
}

Show the user a useful loading or error state. Never assume the network is always available.

Local development and CORS

A browser treats different origins (scheme, host, port) as different security contexts. If a development UI and local FastAPI server use different ports, configure FastAPI CORS for the intended development origin. Bind a packaged local service to loopback, not every network interface, unless you have a carefully secured reason otherwise.

Practice it

Add a response.ok check and a try/catch to a small GET function. In words, explain the difference between a network failure and a response with HTTP status 500.

Show answer guidance

A network failure may prevent fetch from producing a normal response; an HTTP 500 is a response whose server-side operation failed. Check response.ok for HTTP status, and use catch for rejected fetch/parsing/explicitly thrown errors.
