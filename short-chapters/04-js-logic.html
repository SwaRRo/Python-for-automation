Chapter 04 · Foundations

Decisions, functions, and useful array methods

Programs make choices, reuse named operations, and transform lists. These ideas show up in every React application, from a checklist to a desktop ERP.

Estimated time: 40–55 minRead, type, explain, practice
Concise version. This preserves the earlier, shorter lesson. Open the expanded Chapter 04 lesson for the full walkthrough.

By the end, you can…

  • Write conditions using strict comparisons.
  • Define and call ordinary and arrow functions.
  • Use map, filter, and find for different list jobs.

Conditions decide what happens ¶

An if statement runs a block only when its condition is true. Use === for equality and !== for inequality; they do not silently coerce unlike values.

const available = 8;
const requested = 5;

if (requested <= available) {
  console.log("Enough capacity");
} else {
  console.log("Choose a smaller amount");
}

Other useful operators are && (and), || (or), and ! (not). Write clear branches before shortening them into a ternary expression.

Functions package one job ¶

A function can accept parameters and return a result. A parameter is the named input; an argument is the actual value supplied when calling it.

function isAllowed(requested, available) {
  return requested > 0 && requested <= available;
}

const allowed = isAllowed(5, 8); // true

The arrow function form is common in React and callbacks:

const isAllowed = (requested, available) => {
  return requested > 0 && requested <= available;
};

const labelFor = (done) => done ? "Done" : "Open";

When an arrow body has one expression, braces and return can be omitted. When you use braces, remember to write return if a result is needed.

Choose the array method by intent ¶

map transforms every item and returns a new array of the same length. filter keeps matching items. find returns the first match or undefined.

const titles = tasks.map((task) => task.title);
const openTasks = tasks.filter((task) => !task.done);
const selected = tasks.find((task) => task.id === selectedId);

In React, map commonly turns records into elements:

{tasks.map((task) => (
  <li key={task.id}>{task.title}</li>
))}

The key should be a stable unique ID from the data, not usually the array index. React uses it to match records when the list changes.

Common mistake: no return

items.map(item => { <li>...</li> }) returns nothing because the braces start a function body. Use parentheses for an implicit return, or put an explicit return inside the braces.

Practice it

Write a function that accepts a list of tasks and returns only unfinished tasks. Then create a second array containing only their titles. Explain which operation should use filter and which should use map.

Show answer guidance

First use const open = tasks.filter(task => !task.done); then use const titles = open.map(task => task.title). Filtering selects records. Mapping changes the shape of each selected record.
