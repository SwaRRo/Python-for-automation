Chapter 07 · Core skill

React state, forms, and data-driven screens

State is the information a component remembers. When you update state with its setter, React renders again so the screen reflects the new information.

Estimated time: 45–65 minRead, type, explain, practice
Concise version. This preserves the earlier, shorter lesson. Open the expanded Chapter 07 lesson for the full walkthrough.

By the end, you can…

  • Use useState for changing UI data.
  • Update arrays and objects immutably.
  • Build controlled inputs and show loading/error/success states.

State is memory with a setter ¶

Use useState for values that change while the component is being used. React gives you the current value and a setter function.

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

Do not set state by mutating an existing array or object. Create a replacement value. React can then compare references and determine that it should render the new state.

setTasks((current) =>
  current.map((task) =>
    task.id === selectedId ? { ...task, done: true } : task
  )
);

The spread expression {...task} copies the existing fields into a new object before replacing done.

Controlled form inputs ¶

A controlled input gets its value from React state and notifies React when it changes.

const [title, setTitle] = useState("");

<label>
  Task title
  <input
    value={title}
    onChange={(event) => setTitle(event.target.value)}
  />
</label>

For a form, prevent the browser’s default page navigation in the submit handler, validate what you can in the UI, then call your async save function. The backend must validate again—client-side validation is for usability, not trust.

Loading data and representing uncertainty ¶

When a component appears, useEffect can start loading external data. Keep distinct state for data, loading, and error so the UI tells the truth.

const [tasks, setTasks] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState("");

useEffect(() => {
  async function load() {
    try {
      const response = await fetch("/api/tasks");
      if (!response.ok) throw new Error("Could not load tasks");
      setTasks(await response.json());
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }
  load();
}, []);

In a real app, also think about cancellation or stale requests when the component unmounts, duplicate submissions, and refreshing state after a save. For a first feature, a clear loading/error path and reliable response handling are the key concepts.

State is not the database

React state disappears when the app closes unless you save it somewhere. A successful screen update does not prove a database write happened. Treat the backend response as the authoritative saved record.

Practice it

Add a controlled text input and submit button to a task list. On submit, reject a blank title, append a new record with a unique ID using a state setter, and clear the input. Then explain why this local-only example is not persistent.

Show answer guidance

Use setTasks(current => [...current, newTask]) to make a new array, not tasks.push(newTask). The example is local-only because it updates React memory but makes no backend/database request. The capstone adds persistence.
