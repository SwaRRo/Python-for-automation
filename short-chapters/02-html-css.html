Chapter 02 · Foundations

HTML, CSS, and the browser

Before React, learn the browser’s basic materials: semantic markup, forms, and styles. React will still use these same browser elements.

Estimated time: 35–50 minRead, type, explain, practice
Concise version. This preserves the earlier, shorter lesson. Open the expanded Chapter 02 lesson for the full walkthrough.

By the end, you can…

  • Build a meaningful HTML page using headings, labels, inputs, buttons, and lists.
  • Explain selectors, the box model, and a responsive layout.
  • Recognize accessibility habits that matter in forms.

HTML describes meaning and structure ¶

An HTML element usually has an opening tag, content, and a closing tag. A browser parses elements into a document tree. Choose tags for meaning: <main> for primary content, <nav> for navigation, <form> for input, and <button> for an action.

<form>
  <label for="task-title">Task title</label>
  <input id="task-title" name="title" required>
  <button type="submit">Save task</button>
</form>

The for value on a label matches the input’s id. This makes the label clickable and gives assistive technology a clear name for the field. A placeholder is not a replacement for a label.

CSS is a set of presentation rules ¶

CSS rules select elements and assign properties. A class is a reusable label; an ID should usually identify one unique element. The cascade decides which matching rule wins based on origin, importance, specificity, and order. Avoid solving every style conflict with increasingly specific selectors.

.task-form {
  display: grid;
  gap: 0.75rem;
  max-width: 34rem;
}

.task-form input {
  padding: 0.7rem;
  border: 1px solid #9aabb4;
  border-radius: 0.4rem;
}

The box model is content + padding + border + margin. Most projects set box-sizing: border-box so declared widths include padding and border. Use Flexbox for one-dimensional alignment and CSS Grid for rows and columns. Add responsive rules so controls remain usable on narrow screens.

What the browser does ¶

The browser loads an HTML document, downloads linked CSS and JavaScript, builds the document and style trees, and paints pixels. When you click a button, the browser fires an event; JavaScript can respond. Developer Tools let you inspect the DOM, CSS rules, console errors, and network requests.

React does not replace HTML or the browser. JSX looks like markup, but it is JavaScript syntax that React turns into browser UI. Attributes like HTML class become React’s className; a React component returns markup-like JSX.

Common mistake

Do not use a clickable <div> when a button is the correct control. Native buttons support keyboard activation and communicate intent to assistive technology.

Practice it

Create a static page with a heading “Tasks,” a labeled title field, a priority select, a Save button, and a list with two example rows. Use semantic elements and style the form with a small amount of CSS.

Show answer guidance

Check that every field has a visible label, the button is a real button, headings follow a sensible order, and the page remains readable when the viewport is narrow. Do not add React yet; this lesson is about browser fundamentals.
